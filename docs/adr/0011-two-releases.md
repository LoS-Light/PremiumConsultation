# ADR-011: Deliver in two releases, v1.0.0 then v1.1.0

The assignment brief splits its requirements into general and senior, and they disagree on the entry point: the general list makes the Figma screen the entry point, while the senior list asks for a Home button gated by a feature flag. We ship the general requirements as `v1.0.0` (Consultation screen as entry point), merged into `main`, tagged and released by the author, then build the senior requirements on `dev` and ship them as `v1.1.0` (Home entry button, flag, de-duplicated dialog, infinite scroll), whose `dev` → `main` PR goes to the interviewer. This meets each requirement as written instead of picking one entry point over the other, at the cost that the interviewer reviews `v1.0.0` through its ticket PRs and tag rather than an open PR; the README explains both releases.

Error handling also moves to `v1.1.0`, although the brief lists it among the general requirements: `v1.0.0` reads hardcoded data that cannot fail, so the author chose to ship the error view, Retry and the demo failure switch together with the other `v1.1.0` work. The README and the `v1.0.0` release notes state this gap.
